\subsection{Excepciones Encadenadas}

\subsubsection{Regla: preservar la excepción original como causa}

\textbf{Regla:} Al lanzar una excepción personalizada a partir de una excepción capturada, es obligatorio pasar la excepción original como \texttt{innerException} en el constructor, para no perder la traza que originó el error.

\textbf{Descripción:} Microsoft recomienda incluir la excepción original como excepción interna al lanzar una nueva excepción desde un bloque \texttt{catch}, de manera que quien la reciba pueda inspeccionar la causa raíz (Microsoft, 2025a).

\textbf{Código correcto:}
\begin{lstlisting}[style=csharpstyle]
try
{
    _board.SaveState(currentState);
}
catch (IOException ex)
{
    throw new GameStateException("Failed to persist game state.", ex);
}
\end{lstlisting}

\textbf{Código incorrecto:}
\begin{lstlisting}[style=csharpstyle]
try
{
    _board.SaveState(currentState);
}
catch (IOException ex)
{
    throw new GameStateException("Failed to persist game state: " + ex.Message);
}
\end{lstlisting}

\subsubsection{Regla: \texttt{throw;} en lugar de \texttt{throw ex;}}

\textbf{Regla:} Al relanzar la misma excepción capturada sin envolverla en una nueva, deberá usarse la sentencia \texttt{throw;} sin especificar la variable.

\textbf{Descripción:} Microsoft advierte que \texttt{throw ex;} reinicia la traza de la pila en el punto actual, mientras que \texttt{throw;} conserva la traza original completa (Microsoft, 2025a).

\textbf{Código correcto:}
\begin{lstlisting}[style=csharpstyle]
try
{
    _board.MovePlayer(player, destination);
}
catch (InvalidMoveException ex)
{
    _logger.Error($"Unrecoverable move failure for {player.Name}: {ex.Message}");
    throw;
}
\end{lstlisting}

\textbf{Código incorrecto:}
\begin{lstlisting}[style=csharpstyle]
try
{
    _board.MovePlayer(player, destination);
}
catch (InvalidMoveException ex)
{
    _logger.Error($"Unrecoverable move failure for {player.Name}: {ex.Message}");
    throw ex;
}
\end{lstlisting}
