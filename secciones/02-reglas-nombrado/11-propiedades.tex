\subsection{Propiedades}

\subsubsection{Regla: PascalCase y acceso mínimo necesario}

\textbf{Regla:} Las propiedades se nombran en \texttt{PascalCase} con un sustantivo, frase nominal o adjetivo. Si su valor no cambia después de construir el objeto, se expone solo \texttt{get} o se utiliza \texttt{init}; no se agrega un \texttt{set} público innecesario (Microsoft, 2025f).

\textbf{Código correcto:}
\begin{lstlisting}[style=csharpstyle]
public sealed class PlayerProfile
{
    public PlayerProfile(string displayName)
    {
        DisplayName = displayName;
    }

    public string DisplayName { get; }
}
\end{lstlisting}

\textbf{Código incorrecto:}
\begin{lstlisting}[style=csharpstyle]
public sealed class PlayerProfile
{
    public string displayName { get; set; }
}
\end{lstlisting}

\subsubsection{Regla: modificación controlada con \texttt{private set}}

\textbf{Regla:} Cuando una propiedad cambia durante la partida, se mantiene el \texttt{get} público y se restringe el \texttt{set} al menor nivel necesario. La modificación del estado de dominio se realiza mediante un método que expresa la operación (Microsoft, 2025f).

\textbf{Código correcto:}
\begin{lstlisting}[style=csharpstyle]
public sealed class Player
{
    public int Score { get; private set; }

    public void AddScore(int points)
    {
        Score += points;
    }
}
\end{lstlisting}

\textbf{Código incorrecto:}
\begin{lstlisting}[style=csharpstyle]
public sealed class Player
{
    public int Score { get; set; }
}
\end{lstlisting}

\subsubsection{Regla: propiedad totalmente mutable en objetos de datos}

\textbf{Regla:} Cuando la clase solo transporta datos y no protege ninguna invariante de dominio --- una configuración, un objeto de transferencia (DTO) ---, la propiedad expone \texttt{get} y \texttt{set} públicos mediante una propiedad autoimplementada, sin envolverla en un método de acceso manual (Microsoft, 2025f).

\textbf{Código correcto:}
\begin{lstlisting}[style=csharpstyle]
public sealed class GameSettings
{
    public int BoardSize { get; set; }
    public bool SoundEnabled { get; set; }
}
\end{lstlisting}

\textbf{Código incorrecto:}
\begin{lstlisting}[style=csharpstyle]
public sealed class GameSettings
{
    private int _boardSize;
    private bool _soundEnabled;

    public int GetBoardSize() => _boardSize;
    public void SetBoardSize(int value) => _boardSize = value;
    public bool GetSoundEnabled() => _soundEnabled;
    public void SetSoundEnabled(bool value) => _soundEnabled = value;
}
\end{lstlisting}

\subsubsection{Regla: cuerpo de expresión solo en catálogos de diccionario}

\textbf{Regla:} El cuerpo de expresión (\texttt{=>}) en una propiedad se usa únicamente en un catálogo de diccionario: una clase cuyas propiedades de solo lectura exponen, cada una, una entrada de un diccionario de clave y valor, como un archivo de recursos o una tabla de configuración. Cada propiedad consulta su entrada en cada acceso mediante un método privado que recibe la clave. Fuera de un catálogo de diccionario, un valor que se calcula a partir de otros miembros se obtiene mediante un método (Sección 2.2.1). Prohibido almacenar la entrada del diccionario en una propiedad autoimplementada, ya sea con un inicializador (\mbox{\texttt{\{ get; \} =}}) o desde el constructor (Microsoft, 2025f).

\textbf{Descripción:} El cuerpo de expresión consulta el diccionario en cada acceso, por lo que la propiedad refleja cualquier cambio de su contenido, como un cambio de idioma durante la partida; una propiedad autoimplementada guarda la entrada una sola vez y la conserva aunque el diccionario cambie.

\textbf{Código correcto:}
\textit{Archivo \texttt{TextCatalog.cs}:}
\begin{lstlisting}[style=csharpstyle]
public sealed class TextCatalog
{
    private readonly ITextDictionary _dictionary;

    public TextCatalog(ITextDictionary dictionary)
    {
        _dictionary = dictionary;
    }

    public string BoardLabel => GetEntry(nameof(BoardLabel));

    public string TurnLabel => GetEntry(nameof(TurnLabel));

    private string GetEntry(string key)
    {
        return _dictionary.FindEntry(key) ?? key;
    }
}
\end{lstlisting}

\textit{Archivo \texttt{GameSession.cs}:}
\begin{lstlisting}[style=csharpstyle]
public sealed class GameSession
{
    private readonly List<Player> _players;

    public GameSession(List<Player> players)
    {
        _players = players;
    }

    public int CountActivePlayers()
    {
        return _players.Count(player => player.IsActive);
    }
}
\end{lstlisting}

\textbf{Código incorrecto:}
\textit{Archivo \texttt{TextCatalog.cs}:}
\begin{lstlisting}[style=csharpstyle]
public sealed class TextCatalog
{
    private readonly ITextDictionary _dictionary;

    public TextCatalog(ITextDictionary dictionary)
    {
        _dictionary = dictionary;
        BoardLabel = GetEntry(nameof(BoardLabel));
        TurnLabel = GetEntry(nameof(TurnLabel));
    }

    public string BoardLabel { get; }

    public string TurnLabel { get; }

    private string GetEntry(string key)
    {
        return _dictionary.FindEntry(key) ?? key;
    }
}
\end{lstlisting}

\textit{Archivo \texttt{GameSession.cs}:}
\begin{lstlisting}[style=csharpstyle]
public sealed class GameSession
{
    private readonly List<Player> _players;

    public GameSession(List<Player> players)
    {
        _players = players;
    }

    public int ActivePlayerCount => _players.Count(player => player.IsActive);
}
\end{lstlisting}

\textbf{Qué es un catálogo de diccionario:} Una clase cuyo único propósito es exponer entradas de un diccionario cuyo contenido puede cambiar mientras el programa se ejecuta, como un archivo de recursos que cambia con el idioma. Una clase que guarda valores fijos, aunque vengan de un archivo de recursos que no cambia con el idioma, no es un catálogo y usa propiedades autoimplementadas (Sección 2.3.2).

\textbf{Excepción:} Se permite el cuerpo de expresión fuera de un catálogo cuando un tercero exige que el valor sea una propiedad y no un método:
\begin{itemize}
    \item \textbf{Interfaz:} la interfaz declara la propiedad, como \texttt{IAccountRepository Accounts \{ get; \}}.
    \item \textbf{Enlace de datos:} la vista enlaza el valor por el nombre de la propiedad, como en un modelo de vista (MVVM).
    \item \textbf{Framework:} el framework necesita la propiedad para funcionar, como un \texttt{DbSet<T>} de Entity Framework Core, cuya alternativa obligaría a usar el operador \texttt{!} que prohíbe la Sección 9.4.1.
\end{itemize}

\textbf{Alcance:} La regla trata el cuerpo de expresión de la propiedad completa (\texttt{public int Total => ...;}). No aplica a los accesores escritos con cuerpo de expresión (\texttt{get => \_value;} y \texttt{set => \_value = value;}), que equivalen a \texttt{get \{ return \_value; \}} y solo reenvían a un estado interno.

\textbf{Código correcto (enlace de datos):}
\begin{lstlisting}[style=csharpstyle]
public sealed class LobbyViewModel : ViewModel
{
    public bool IsWaiting
    {
        get => Get<bool>();
        set => Set(value);
    }

    [DependsOn(nameof(IsWaiting))]
    public bool IsReady => !IsWaiting;
}
\end{lstlisting}

\textbf{Código incorrecto (enlace de datos):}
\begin{lstlisting}[style=csharpstyle]
public sealed class LobbyViewModel : ViewModel
{
    public bool IsWaiting
    {
        get => Get<bool>();
        set => Set(value);
    }

    public bool IsReady()
    {
        return !IsWaiting;
    }
}
\end{lstlisting}
