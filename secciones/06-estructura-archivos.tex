\section{Estructura de Archivos}

\subsection{Regla: un tipo de nivel superior por archivo}

\textbf{Regla:} Cada archivo contiene exactamente un tipo de nivel superior: clase, interfaz, \texttt{record}, \texttt{struct}, \texttt{enum} o \texttt{delegate}. El nombre del archivo coincide con el del tipo; en un tipo genérico se omiten los parámetros de tipo, de modo que \texttt{ServiceChannel<TContract>} se guarda en \texttt{ServiceChannel.cs} (McConnell, 2004).

\textbf{Tipos anidados:} Prohibido declarar un tipo anidado visible fuera de la clase que lo contiene (\texttt{public}, \texttt{internal} o \texttt{protected}); un tipo que otras clases usan se declara en su propio archivo. Se permite un tipo anidado \texttt{private} que solo sirve a la clase que lo contiene. El analizador \texttt{CA1034} detecta los tipos anidados visibles (Microsoft, s.~f.-a).

\textbf{Código generado:} Los archivos que produce una herramienta, como \texttt{Strings.Designer.cs} a partir de un archivo \texttt{.resx}, quedan exentos de esta sección porque se regeneran en cada cambio y cualquier corrección manual se pierde.

\textbf{Código correcto (archivo \texttt{TurnManager.cs}):}
\begin{lstlisting}[style=csharpstyle]
namespace BoardGame.Logic;

public sealed class TurnManager
{
}
\end{lstlisting}

\textbf{Código incorrecto (archivo \texttt{GameLogic.cs}):}
\begin{lstlisting}[style=csharpstyle]
namespace BoardGame.Logic;

public sealed class TurnManager
{
    public sealed class TurnSnapshot
    {
    }
}

public sealed class ScoreBoard
{
}
\end{lstlisting}

\subsection{Regla: orden de los elementos dentro de la clase}

\textbf{Regla:} Orden fijo dentro de una clase: constantes, campos estáticos, campos de instancia, constructores, propiedades estáticas, propiedades de instancia, eventos, métodos y, al final, tipos anidados privados (McConnell, 2004).

\textbf{Código correcto:}
\begin{lstlisting}[style=csharpstyle]
public sealed class DiceRoller
{
    private const int MinimumFaceValue = 1;

    private static readonly Random _random = Random.Shared;

    private readonly int _maximumFaceValue;

    public DiceRoller(int maximumFaceValue)
    {
        _maximumFaceValue = maximumFaceValue;
    }

    public static int StandardFaceCount { get; } = 6;

    public int LastRoll { get; private set; }

    public event EventHandler? DiceRolled;

    public int Roll()
    {
        LastRoll = _random.Next(MinimumFaceValue, _maximumFaceValue + 1);
        DiceRolled?.Invoke(this, EventArgs.Empty);
        return LastRoll;
    }
}
\end{lstlisting}

\textbf{Código incorrecto:}
\begin{lstlisting}[style=csharpstyle]
public sealed class DiceRoller
{
    public event EventHandler? DiceRolled;

    public int Roll()
    {
        LastRoll = _random.Next(MinimumFaceValue, _maximumFaceValue + 1);
        DiceRolled?.Invoke(this, EventArgs.Empty);
        return LastRoll;
    }

    private readonly int _maximumFaceValue;

    public int LastRoll { get; private set; }

    public DiceRoller(int maximumFaceValue)
    {
        _maximumFaceValue = maximumFaceValue;
    }

    public static int StandardFaceCount { get; } = 6;

    private const int MinimumFaceValue = 1;
    private static readonly Random _random = Random.Shared;
}
\end{lstlisting}

\subsection{Regla: orden y continuidad de directivas \texttt{using}}

\textbf{Regla:} Las directivas \texttt{using} se colocan fuera del espacio de nombres en un único bloque sin líneas en blanco. Primero van los espacios de nombres de \texttt{System}, en orden alfabético; después, todos los demás en un solo grupo alfabético, sin separar bibliotecas de terceros y espacios de nombres propios del proyecto (Microsoft, 2022a; Microsoft, 2022b). El orden alfabético no distingue mayúsculas de minúsculas, por lo que \texttt{log4net} va después de \texttt{CoreWCF} y antes de \texttt{Microsoft}.

\textbf{Descripción:} Es el orden que produce el comando de ordenar \texttt{using} del editor con la configuración siguiente, de modo que no requiere revisión manual:

\begin{itemize}
  \item \texttt{csharp\_using\_directive\_placement = outside\_namespace}
  \item \texttt{dotnet\_sort\_system\_directives\_first = true}
  \item \texttt{dotnet\_separate\_import\_directive\_groups = false}
\end{itemize}

\textbf{Código correcto:}
\begin{lstlisting}[style=csharpstyle]
using System;
using System.Collections.Generic;
using BoardGame.Core;
using log4net;
using Microsoft.Extensions.DependencyInjection;

namespace BoardGame.Services;
\end{lstlisting}

\textbf{Código incorrecto:}
\begin{lstlisting}[style=csharpstyle]
using log4net;

using System.Collections.Generic;
using Microsoft.Extensions.DependencyInjection;
using BoardGame.Core;
using System;

namespace BoardGame.Services;
\end{lstlisting}

\subsection{Regla: agrupación mediante espacios de nombres}

\textbf{Regla:} Todo tipo pertenece a un espacio de nombres que coincide con la carpeta en la que está el archivo, a partir de la carpeta raíz del proyecto, y que refleja la responsabilidad del archivo. Se usa la declaración de ámbito de archivo y un solo espacio de nombres por archivo; por ejemplo, los servicios de guardado en la carpeta \texttt{Services/Saves} se agrupan bajo \texttt{BoardGame.Services.Saves} (Microsoft, 2026d).

\textbf{Descripción:} La compilación verifica ambas condiciones: \texttt{IDE0161} exige la declaración de ámbito de archivo y \texttt{IDE0130} exige que el espacio de nombres coincida con la carpeta (Microsoft, s.~f.-b; Microsoft, s.~f.-c). La configuración equivalente es:

\begin{itemize}
  \item \texttt{csharp\_style\_namespace\_declarations = file\_scoped}
  \item \texttt{dotnet\_style\_namespace\_match\_folder = true}
\end{itemize}

\textbf{Código correcto (archivo \texttt{Services/Saves/SaveGameService.cs}):}
\begin{lstlisting}[style=csharpstyle]
namespace BoardGame.Services.Saves;

public sealed class SaveGameService
{
}
\end{lstlisting}

\textbf{Código incorrecto (archivo \texttt{Services/Saves/SaveGameService.cs}):}
\begin{lstlisting}[style=csharpstyle]
namespace BoardGame
{
    public sealed class SaveGameService
    {
    }
}
\end{lstlisting}
